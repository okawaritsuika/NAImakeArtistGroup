# 그림체 관리 개편 제작 방침

## 1. 목적

이 개편은 다음 두 가지 요구를 만족하는 것을 목적으로 한다.

1. 수집된 공유 그림체의 모든 이미지를 게시물 단위가 아닌 하나의 연속된 갤러리에서 확인한다.
2. 사용자가 직접 정리한 그림체를 추가하고, 자동 생성 결과나 공유 그림체 중 마음에 드는 항목을 별도의 확정 그림체로 관리한다.

이 문서는 구현 전 합의된 제작 방침이다. 이 문서 작성 단계에서는 프로그램 코드와 데이터베이스를 변경하지 않는다.

## 2. 그림체 관리의 전체 구조

그림체 관리를 다음 세 개의 탭으로 나눈다.

1. `제작 기록`: 그림체 제작에서 자동 생성된 결과
2. `확정 그림체`: 사용자가 최종 확인하고 보관하기로 한 그림체
3. `공유 그림체`: 수집된 공유 그림체의 전체 이미지

각 탭의 데이터는 서로 독립적으로 취급한다. 제작 기록이나 공유 그림체를 확정할 때 원본을 삭제하거나 옮기지 않고, 확정 그림체에 별도의 복사본을 만든다.

## 3. 제작 기록 탭

### 3.1 표시 단위

- 생성 결과 이미지 한 장을 카드 하나로 표시한다.
- 같은 작가 조합으로 여러 번 생성했더라도 각 결과를 별도의 카드로 표시한다.
- 카드에는 생성 이미지와 `작가 7명` 같은 작가 수를 표시한다.
- 기존의 `이미지 1장` 표시는 제거한다.
- 작가 조합이 같다는 이유로 여러 생성 결과를 하나의 카드로 합치지 않는다.

### 3.2 상세 정보

- 카드를 클릭하면 선택한 이미지의 상세 정보를 오른쪽 영역에 표시한다.
- 상세 정보에는 이미지와 저장된 프롬프트 및 생성 설정을 표시한다.
- 생성 설정에는 최소한 다음 항목이 포함된다.
  - 샘플러
  - 스케줄러
  - Steps
  - CFG Scale
  - CFG Rescale
  - Variety+
  - 모델
  - 해상도
  - 시드
- `확정 그림체로 추가` 기능을 제공한다.
- 이미 확정 그림체로 추가한 생성 결과에는 확정 여부를 알아볼 수 있는 표시를 제공한다.

## 4. 확정 그림체 탭

### 4.1 확정 그림체의 기본 단위

- 확정 그림체 하나는 대표 이미지 한 장을 가진다.
- 하나의 확정 그림체에 여러 대표 이미지를 넣는 기능은 이번 범위에 포함하지 않는다.
- 확정 그림체는 제작 기록이나 공유 그림체의 원본과 독립적으로 수정하고 삭제할 수 있다.

### 4.2 확정 그림체가 만들어지는 경로

확정 그림체는 다음 세 가지 방법으로 추가할 수 있다.

1. 제작 기록의 생성 결과를 `확정 그림체로 추가`
2. 공유 그림체의 이미지를 `확정 그림체로 추가`
3. 확정 그림체 탭의 `그림체 추가` 버튼으로 사용자가 직접 추가

제작 기록 또는 공유 그림체에서 추가할 때는 원본을 유지하고 확정 그림체에 복사한다.

### 4.3 직접 추가 모달

`그림체 추가` 버튼을 누르면 전용 모달을 연다.

- 이미지 파일을 드래그 앤 드롭할 수 있다.
- 클립보드의 이미지를 붙여넣을 수 있다.
- 이미지에서 NovelAI 메타데이터를 찾으면 프롬프트와 생성 설정을 자동으로 채운다.
- 메타데이터가 없거나 일부만 추출되면 나머지 항목을 사용자가 직접 입력할 수 있다.
- 자동 추출 성공 여부와 추출하지 못한 항목을 명확하게 표시한다.
- 저장하기 전에 모든 항목을 검토하고 수정할 수 있다.

클립보드 복사, 이미지 편집, 형식 변환 등을 거친 파일은 메타데이터가 사라질 수 있으므로 이미지 등록 자체와 메타데이터 추출 성공 여부를 분리한다. 메타데이터 추출 실패는 이미지 등록 실패로 처리하지 않는다.

### 4.4 확정 전 편집 항목

확정 모달에서 다음 정보를 확인하고 수정할 수 있게 한다.

- 그림체 이름
- 사용자 설명
- 대표 이미지
- 작가 프롬프트
- 적용 중인 퀄리티 프롬프트
- 제외된 퀄리티 태그
- 고정 프롬프트
- 네거티브 프롬프트
- 샘플러
- 스케줄러
- Steps
- CFG Scale
- CFG Rescale
- Variety+
- 모델

이미지의 너비·높이·시드는 확정 그림체를 추가할 때 사용자가 관리할 항목에서 제외한다.

### 4.5 퀄리티 프롬프트 복구

- 현재 적용 중인 퀄리티 프롬프트와 제외된 퀄리티 태그를 구분해서 표시한다.
- 제외된 태그는 목록 또는 칩 형태로 보여주고, 선택하면 적용 중인 퀄리티 프롬프트로 복구할 수 있게 한다.
- 새로 생성되는 결과에는 실제 적용된 퀄리티 프롬프트뿐 아니라 원본 퀄리티 프롬프트와 제외 태그 목록도 함께 저장한다.
- 기존 데이터에 제외 기록이 없으면 현재 저장된 프롬프트를 우선 표시하고, 가능한 범위에서만 태그를 분석한다.
- 분석으로 정확히 복구할 수 없는 내용은 자동으로 단정하지 않고 사용자가 직접 입력하게 한다.

## 5. 공유 그림체 탭

### 5.1 갤러리

- 수집된 이미지를 게시물별로 묶지 않고 하나의 연속된 이미지 갤러리로 표시한다.
- 각 수집 이미지가 갤러리의 독립된 항목이 된다.
- 이미지가 많아도 화면과 메모리가 과도하게 느려지지 않도록 페이지 단위로 나누어 표시한다.
- 사용자는 게시물을 하나씩 열지 않고 페이지를 이동하면서 모든 수집 이미지를 확인할 수 있어야 한다.

### 5.2 이미지 상세 정보

- 이미지를 클릭하면 오른쪽 상세 영역에 큰 이미지와 메타데이터를 표시한다.
- 상세 정보에는 다음 내용을 포함한다.
  - 작가·퀄리티 등을 포함한 프롬프트
  - 네거티브 프롬프트
  - 샘플러
  - 스케줄러
  - Steps
  - CFG Scale
  - CFG Rescale
  - Variety+
  - 모델
  - 해상도
  - 시드
  - 원본 게시물 제목과 링크
- 메타데이터가 없는 항목은 오류를 발생시키지 않고 `정보 없음`으로 표시한다.
- 상세 영역에서 해당 이미지를 확정 그림체로 추가할 수 있다.

## 6. 설명 표시 기능

- 그림체 관리 상단에 `설명 표시` 토글을 제공한다.
- 설명을 끄면 제작 기록, 확정 그림체, 공유 그림체를 모두 이미지 중심 카드로 표시한다.
- 설명을 켜면 그림체 이름, 사용자 설명과 프롬프트 요약을 함께 표시한다.
- 사용자가 선택한 표시 상태는 프로그램을 다시 실행한 뒤에도 유지한다.
- 목록 검색과 탭별 분류·정렬 필터를 제공한다. 공유 그림체는 전체 수집 DB를 대상으로 메타데이터와 최소 추천수도 필터링한다.
- 그림 카드 크기는 작게, 보통, 크게 조절할 수 있고 선택한 크기를 유지한다.
- 페이지당 표시 개수는 12개, 24개, 48개, 96개 중에서 고를 수 있고 선택한 값을 유지한다.
- 이미지를 선택하기 전에는 빈 상세 영역을 숨기고 갤러리가 전체 폭을 사용한다. 선택한 뒤에만 상세 영역을 연다.

## 7. Variety+ 지원

### 7.1 그림체 제작

- 그림체 제작의 생성 설정에 Variety+ 토글을 추가한다.
- 생성 요청에 Variety+ 설정을 반영한다.
- 생성 결과를 저장할 때 Variety+ 상태도 함께 저장한다.

### 7.2 저장 방식

- Variety+의 사용자 표시 상태와 NovelAI 요청·메타데이터의 원본 값을 함께 보존한다.
- 메타데이터의 `skip_cfg_above_sigma` 값을 Variety+ 판별과 재현에 사용한다.
- 모델에 따라 실제 요청값이 다를 가능성을 고려하여 원본 수치를 단순 Boolean으로 덮어쓰지 않는다.
- 기존 데이터처럼 Variety+ 정보가 전혀 없는 경우 `꺼짐`으로 단정하지 않고 `알 수 없음`으로 표시한다.

## 8. 저장 구조와 마이그레이션 원칙

### 8.1 기존 데이터 활용

현재 자동 생성 결과와 공유 그림체에는 다음 생성 설정이 이미 저장되어 있으므로 이를 그대로 활용한다.

- 샘플러
- 스케줄러
- Steps
- CFG Scale
- CFG Rescale
- 모델
- 해상도
- 시드

확정 그림체는 제작 기록 및 공유 그림체의 원본 행을 직접 변경하지 않는 독립 데이터로 저장한다.

### 8.2 하위 호환성

- 새 필드는 누락을 허용하거나 안전한 기본값을 가진다.
- 기존 데이터베이스에 새 필드가 없어도 프로그램 시작과 목록 조회가 실패하지 않아야 한다.
- 기존 이미지와 프롬프트를 삭제하거나 초기화하지 않는다.
- 기존 행에 생성 설정이 일부 없으면 빈 값 또는 `알 수 없음`으로 표시한다.
- 누락된 값은 확정 모달에서 사용자가 직접 입력하고 저장할 수 있다.
- `알 수 없음`과 명시적인 `꺼짐` 또는 숫자 `0`을 서로 다르게 취급한다.

## 9. 오류 처리 원칙

- 이미지 파일은 정상이나 메타데이터가 없는 경우 수동 입력 흐름으로 계속 진행한다.
- 메타데이터 일부만 정상인 경우 추출한 값만 채우고 나머지는 비워 둔다.
- 잘못된 숫자나 지원하지 않는 값은 저장 전에 해당 입력란에서 확인할 수 있게 한다.
- 원본 데이터 분석이 불확실하면 임의의 설정값을 만들어 넣지 않는다.
- 한 항목의 정보가 누락되어도 갤러리 전체나 상세 화면이 열리지 않는 문제가 생기지 않아야 한다.

## 10. 이번 개편의 완료 기준

다음 조건을 모두 만족하면 구현이 완료된 것으로 본다.

1. 그림체 관리가 제작 기록, 확정 그림체, 공유 그림체의 세 탭으로 구분된다.
2. 제작 기록에서 생성 이미지 한 장이 카드 하나로 표시되고, 같은 작가 조합도 각각 분리된다.
3. 제작 기록 카드에서 `이미지 1장` 문구가 사라지고 작가 수가 표시된다.
4. 공유 그림체의 모든 수집 이미지를 게시물 구분 없이 연속된 갤러리에서 볼 수 있다.
5. 제작 기록과 공유 그림체의 이미지를 원본을 유지한 채 확정 그림체로 복사할 수 있다.
6. 사용자가 이미지를 드래그하거나 붙여넣어 확정 그림체를 직접 추가할 수 있다.
7. 이미지 메타데이터를 추출하고, 추출하지 못한 값은 수동으로 입력할 수 있다.
8. 확정 그림체는 대표 이미지 한 장을 가진다.
9. 퀄리티 프롬프트에서 제외했던 태그를 확인하고 복구할 수 있다.
10. 그림체 제작에서 Variety+를 설정할 수 있고 결과에 설정이 저장된다.
11. 설명 표시를 켜고 끌 수 있으며 선택 상태가 유지된다.
12. 새 정보가 없는 기존 데이터도 오류 없이 표시하고 수정할 수 있다.
13. 마이그레이션 후에도 기존 제작 기록, 공유 그림체, 이미지 파일이 보존된다.

## 11. 이번 문서에서 제외한 사항

- 실제 프로그램 코드 수정
- 데이터베이스 마이그레이션 실행
- EXE 빌드 및 배포
- 확정 그림체에 여러 대표 이미지를 넣는 기능
- 합의되지 않은 추가 검색, 정렬, 분류 기능

위 항목은 이 제작 방침에 따른 구현 단계에서 별도로 진행한다.
