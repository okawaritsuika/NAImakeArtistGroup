# 공유 그림체 이미지팩 배포

앱 v0.1.10부터 Hugging Face Datasets의 `okawaritsuika/nai-shared-styles`에서 WebP 이미지팩을 받습니다. 아카라이브 원본 다운로드 API와 기존 `/image-archive/google` API 별칭은 유지합니다.

## 배포 입력과 검증

1. 공개 공유 의도를 확인한 게시글만 별도 배포 DB로 선택합니다. 개인 DB·메모·로그인 정보·생성 기록을 통째로 배포하지 않습니다. 원본 출처를 보존하고 재배포 금지·공개 부적합 항목은 제외합니다.
2. 원본 DB와 이미지 디렉터리는 읽기 전용 입력으로 사용합니다. 메타데이터 전용 시드는 `export_arca_seed.py`로 내보냅니다. 같은 게시글·안정 이미지 주소의 중복 행을 제거해야 합니다.
3. `build_shared_image_archive.py --seed <배포 시드> --source <원본 DB> <이미지 폴더> --output <출력 폴더> --quality 90 --workers 4`를 실행합니다. `--source`는 여러 번 지정할 수 있습니다.
4. 모든 파일의 해상도와 전체 생성 JSON, 프롬프트·네거티브·캐릭터 프롬프트·모델·생성 설정을 변환 전후 비교합니다. 불일치나 원본 파일 누락은 배포팩 생성을 중단합니다. 변환 결과는 입력 해시와 설정별로 캐시합니다.
5. 최종 ZIP, 메타데이터 전용 시드, `archive_info.json`, 출처·권리·삭제 요청 안내를 포함한 데이터셋 카드를 업로드합니다. 라이선스가 확인되지 않았다면 임의로 CC0 등으로 표시하지 않습니다.
6. 업로드한 커밋의 고정 다운로드 주소와 `archive_info.json`의 용량·해시·파일 수·시드 해시를 `arca_image_archive.py`에 반영합니다. 최종 시드를 저장소의 `arca_style_seed.sqlite`로 사용합니다.
7. 새 DB 설치와 기존 DB 업그레이드, ZIP 이어받기, 파일별 해시·누락 검증, 프런트엔드 테스트를 실행합니다. `build_exe.ps1`은 시드가 이미지팩에 고정된 해시와 다르면 실패합니다.

## 이미지팩 형식

ZIP 형식 2의 `manifest.json`은 파일별 원본 게시글 주소와 서명·만료 시간을 제거한 안정 이미지 주소를 저장합니다. 파일명은 두 주소를 줄바꿈으로 연결한 문자열의 SHA-256에 `.webp`를 붙입니다. DB의 내부 행 번호가 달라지거나 CDN 도메인이 바뀌어도 동일한 이미지의 모든 로컬 행에 연결합니다.

WebP는 품질 90의 손실 압축이며, 프롬프트 저장은 화질 압축과 독립적입니다. 전체 생성 JSON을 UTF-16 BE EXIF UserComment로 옮깁니다. PNG stealth에만 있던 메타데이터도 동일하게 보존합니다. EXIF를 제거하는 외부 편집기로 다시 저장한 파일까지 보존을 보장하지는 않습니다.

신형 팩에 기본 시드 이미지가 빠져 있으면 설치를 거부합니다. 설치 후에도 기본 이미지의 실제 파일 존재 여부를 확인하며, 누락이나 연결 실패가 있으면 경고를 표시하고 ZIP을 보존합니다. 사용자가 별도로 수집한 이미지는 배포팩의 범위에 포함되지 않을 수 있습니다.
